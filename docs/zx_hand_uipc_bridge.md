# ZX Hand UIPC Bridge — Implementation Log

## Architecture

ZX hand collision bridging now uses the same pattern as GelSight gel pads:

```
GelSight:  gelpad ──UipcIsaacAttachments──→ gelsight_mini_case  [collision + sensing]
ZX hand:   gelpad ──UipcIsaacAttachments──→ xense_leftfinger    [collision only]
           rod    ──UipcIsaacAttachments──→ linkage rod body     [collision only]
```

- **`ZxGelpad`** (`envs/utils/zx_gelpad.py`): FEM gel pad (StableNeoHookean, E=0.1) attached to `xense_leftfinger`/`xense_rightfinger` via `UipcIsaacAttachments`. Placed at `/World/envs/env_.*/Robot/zx_gelpad_*` (under Robot, NOT under articulation link → no RigidBodyAPI inheritance → FEM init works).

- **`ZxRodProxy`** (`envs/utils/zx_gelpad.py`): Same pattern for linkage rod bodies. Requires `assets/zx_rod.usd` mesh (generated by `scripts/generate_zx_rod_mesh.py` in Kit runtime). Gracefully skips if mesh not available.

- **`ZxGelpadManager`**: Lifecycle orchestrator — `create_usd_prims()` before env clone, `create_uipc_objects()` after clone/before `setup_sim()`.

- **Robot USD**: Official `franka_zx_hand_real.usd` from `third_party/xense-sim4.5/`. The custom `franka_zx_hand_with_gel.usd` (with inert embedded gel blocks) has been deleted.

- **Config dispatch**: `RobotCfg.use_adaptive_grasp` + `RobotCfg.wrist_camera_prim_path` fields eliminate all per-embodiment `if zxhand` branches in `load_robot_and_sensors()`.

## Key Differences from GelSight (necessary — xense plugin constraints)

| Aspect | GelSight | ZX Hand |
|--------|----------|---------|
| Tactile sensing | `VisualTactileSensor` (VBTS on gel pad) | `OfficialZXTactileSensor` (ortho depth + xensim.FemSensor) |
| Wrist camera | `WristCamera` | `Hand_Camera` (under `right_base_link`) |
| Gripper | Prismatic PD (2 joints) | Angular closed-chain velocity bang-bang (1 driven joint) |
| EE pose source | `panda_hand` body state | cuRobo FK (no `panda_hand` in ZX USD) |
